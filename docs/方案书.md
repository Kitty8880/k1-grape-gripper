# 基于 K1 平台的多模态智能抓取终端

## 摘要

本项目在进迭时空 K1 平台（MUSE Pi Pro 开发板，Bianbu LXQt 系统）上，
实现了一台**多模态协同的具身智能抓取终端**。

用户对终端说"葡萄"，终端在本地完成语音识别、视觉确认、夹持过程实时监控、
力控抓取与目标位置判定，全程无需键盘、显示器或远程连接。

**系统采用"CV + ASR"两种模态，且二者在同一条控制链路中协同**：

- **ASR** 给出"用户想做什么"（意图）；
- **CV** 给出"实际发生了什么"（事实），并**在抓取全程以 3 fps 持续观测**。

**核心技术特征是一个"具身抓取闭环"**：摄像头不再只是抓之前拍一张，
而是持续观察整个夹持过程，与两片压力传感器的 20 Hz 读数在每个节拍融合，
形成时序状态机：

**采基线 → 闭合中 → 接触到 → 夹到了 → 已移到B**

**两条失败分支：闭合阶段判"夹空"，夹住之后判"脱落"。**

其中"夹到了"的判定是**双模态逻辑与**：
压力传感器读数上升 **且** 视觉检测到葡萄边缘被平板压平（轮廓直边占比上升），
两者缺一不判 —— 只有力上升可能是把葡萄推走了，只有边缘变化可能是光照错觉。

"抓取成功"定义为**从 A 点移到 B 点**（预学目标位置 + 停稳确认），
而不只是"夹住了"。

**实测关键数据**（均在真实硬件上测得）：

| 指标 | 实测值 |
|---|---|
| 说完话 → 夹爪开始动作 | **1.33 s** |
| ASR 句/字/意图准确率 | **100 %（各 20 次）** |
| 视觉识别成功率 | **100 %（20 帧）**，误报 0 %（0/10） |
| 抓取成功率 | **100 %（10 次）** |
| 夹持状态三档识别 | **90 %（27/30）**，"夹紧"100 % |
| A→B 到达判定 | 实测成功（距 B 点 35~49 px） |
| 单次任务端到端 | 约 25 s（含搬运到 B 点） |
| AI 模型 | YOLOv8n 1.9 MB，NPU 推理 17~23 ms |

**一个诚实且有价值的工程结论**：项目原本以"防止夹坏物体"为核心安全目标。
实测发现当前舵机（MG996R，5 V 供电）最大夹持力约 1.2~1.4 N，
**低于葡萄的破裂力（估计 3~10 N）**，因此在该硬件范围内"夹坏"并非真实风险。
真正的工程风险是**夹持力不足导致滑落**。
力感知的价值因此从"防止破坏"转移到"确认夹持成功、自适应物体尺寸、识别硬件极限"。

## 一、引言

### 1.1 项目背景

在工业分拣、果蔬采摘、实验室自动化等场景中，"抓取一个柔软物体"
看似简单，实际包含三个环环相扣的问题：

| 问题 | 本质 | 常见失败方式 |
|---|---|---|
| **抓什么** | 目标识别与意图理解 | 抓错物体、没看清就抓（盲夹） |
| **怎么抓** | 力与位置的控制 | 夹不牢滑落、或夹太紧压坏 |
| **抓到没有** | 结果的确认 | 自认为夹住了，其实已滑落 |

传统方案往往只解决其中一环：纯视觉抓取不知道夹了多大力，
纯力控不知道物体在哪，而"抓完就报告成功"更是常见的虚假成功率来源。

### 1.2 问题定义

本项目选择**葡萄**作为目标物体，原因有三：

1. **柔软易变形** —— 是检验"无损抓取"的良好对象；
2. **形状特征明确** —— 圆形、有固定色相，便于视觉处理；
3. **状态会随夹持变化** —— 被压扁时轮廓变直，为"视觉判断夹持状态"提供了物理依据。

**要实现的能力**：

- 听到语音指令后，本地识别意图；
- 用视觉确认目标存在且符合意图；
- 在夹持过程中**持续**判断"是否接触到 / 是否夹住 / 是否滑落"；
- 把物体搬到指定位置，并**确认真的到位**；
- 全程无人干预，断电重启后能自动恢复。

### 1.3 设计目标与约束

| 类别 | 约束 | 应对 |
|---|---|---|
| 算力 | K1 8 核 RISC-V + 2 TOPS NPU | 重计算下沉到 NPU，控制逻辑留在 CPU |
| 传感器 | PS01 单样本噪声 σ≈2.65 N，比目标力（1.2 N）还大 | **全部判据用中位数 + 连续 N 拍确认**，不用单点值 |
| 摄像头 | OV5647 独占（`cam-test` 同时只能一个进程） | 预览复用同一条视频流，不额外占用 |
| 执行器 | MG996R 位置控制，无力度反馈，负载下会 creep | 不追求精确力控，改为"到达即锁存、绝不回退" |
| 散热 | 连续 16 fps 推流曾把板子烧到 79 °C | 视觉限速 3 fps，实测稳定在 58~64 °C |
| 交互 | 交付形态没有屏幕 | 夹爪做手势（招手=就绪、点头=完成）作为状态信号 |

### 1.4 方案总览

**整条链路分四段：**

**第一段 · 听懂**
用户说"葡萄"，本地 SenseVoice 模型识别（约 1.3 s），解析出"抓取"意图。

**第二段 · 确认**
视觉确认目标是否存在、是否与意图一致。
不一致则拒绝执行 —— 避免"语音说夹葡萄、实际面前是别的东西"时盲夹。

**第三段 · 具身抓取闭环（核心）**
摄像头以 3 fps 持续观测，压力传感器以 20 Hz 采样，两者在每个节拍融合：

| 环节 | 判据 |
|---|---|
| 采基线 | 张开状态下实测扁平度基线 |
| 闭合中 | 力未到目标，脉宽逐步减小 |
| **接触到** | **力上升 且 边缘变直** |
| **夹到了** | **力达标 且 边缘更直** |
| **已移到B** | **到达预学位置 且 停稳 且 仍夹着** |
| 夹空 / 脱落 | 分别对应"没有东西可夹"与"夹住后又掉了" |

**第四段 · 确认成功**
"抓取成功"定义为**从 A 点移到 B 点**，而不只是"夹住了"。

**方案的核心主张**：
**"夹到了"必须是两个独立物理量同时变化的结果，才可信。**
这一条贯穿了力感知、视觉和状态机的全部设计。

### 2.2 力感知子系统

#### 2.2.1 传感器接入

PS01 是光学力传感器（ams OSRAM AS7150 光学前端），
通过 UART 持续推送三路光电二极管（PD1/PD2/PD3）读数。

**两步启动是必须的**：先发配置命令，再发启动命令。
只发其中一个，传感器不出数据也不报错 —— 这个坑花了两天才定位。

**稳定设备名用 `by-path`**，否则插拔后 A/B 两只会互换：

```
/dev/serial/by-path/...-port0  → CH340（A，左指）
/dev/serial/by-path/...-port1  → PL2303（B，右指）
```

#### 2.2.2 噪声特性与应对

| 指标 | 实测值 | 结论 |
|---|---|---|
| 单次采样噪声 | **σ = 2.65 N** | 比目标夹持力（1.2 N）还大，**单点值不可用** |
| 0.8 s 平均后 | **σ = 0.24 N** | 可用 |
| 灵敏度 | 1,564 计数/N | 258 g 已知质量标定 |
| 两只传感器噪声相关 | ρ = **+0.279** | 弱相关 |
| 双传感器**平均**降噪 | **31 %** | ✅ 采用 |
| 双传感器**差分**降噪 | −5 % | ❌ 实测无效，放弃 |

**关键设计：所有力判据用中位数，不用均值，也不用单点。**

```python
sustained = statistics.median(force_hist[-3:])    # 最近 3 拍中位数
```

**为什么不用均值**：PS01 每 2 秒会出现周期性尖峰，
均值会被尖峰拉高；中位数对离群点不敏感。

### 2.3 视觉子系统

#### 2.3.1 两个任务，主任务不是定位

| 任务 | 帧率 | 方法 | 输出 |
|---|---|---|---|
| **① 夹持状态判定（主）** | **3 fps 持续** | **轮廓几何 → 扁平度** | 自由 / 贴住 / 夹紧 |
| ② 葡萄定位（辅助） | 同上，复用同一帧 | HSV 掩码 + 圆形度筛选 | 质心、宽度 |

#### 2.3.2 边缘几何：为什么不用 Canny 或深度学习

**物理依据**：葡萄被两指压平时，边界由**圆弧**变成**直线段**。

```
提取轮廓 → 多边形近似（approxPolyDP, eps=0.015）
        → 量"最长直边 / 周长"（扁平度）
        → 自由 0.13 → 夹紧 0.19（实测中位数）
```

| 候选方法 | 问题 |
|---|---|
| **Canny / Sobel** | 该摄像头清晰度仅约 40（Laplacian），Canny 边缘是碎的，无法稳定量直边长度 |
| **YOLOv8n** | 只输出边界框，给不出"轮廓有多直"；遮挡一半即失效 |
| **轮廓几何** | 颜色分割能得到**闭合**边界，多边形近似后直边清晰可测；**无需训练** |

**实测准确率：三档分类 90 %（27/30），"夹紧"100 % 可分。**

**阈值标定方法**：对 30 张受控照片做一维双阈值穷举搜索，
以最大化三类正确率为目标，得到 `free_max=0.1442`、`touch_max=0.1611`。

#### 2.3.3 三个必须处理的工程细节

**① 基线必须现场实测，不能写死**

同一"自由状态"在不同来源下扁平度差别很大：

| 来源 | 自由状态扁平度 |
|---|---|
| 存档照片 | 0.130 |
| 实时流 | **0.147** |
| 误锁黑色传感器块时 | **0.259** |

**所以判据用相对基线的增量（≥0.015），不用绝对阈值。**

**② 分"捕获/跟踪"两套阈值**

葡萄被夹扁后圆度会从 0.8 掉到 0.5 以下。
严格阈值（圆度 ≥0.60）会导致"夹紧后视觉丢失"。
**跟踪期放宽到 0.42**，解决了这个问题。

**③ 拒收被画面边缘切掉的轮廓**

轮廓贴边会产生假的直边，扁平度从 0.14 虚高到 0.28，
但圆度、尺寸都正常，所有筛选都放它过去。
**检出贴边即拒绝，并明确报出"被画面哪个边缘切掉"。**

### 2.4 语音子系统

#### 2.4.1 本地部署

| 项 | 值 |
|---|---|
| 模型 | SenseVoice（量化后 466 MB） |
| 部署 | 完全本地，不联网 |
| 推理耗时 | 1.37 s（音频 1.66 s，RTF 0.82） |
| NPU 加速 | RTF 0.82 → 0.81，**无收益**（内存瓶颈） |
| 准确率 | **100 %（句/字/意图，各 20 次）** |

#### 2.4.2 两个必须避开的坑

**① 采样率**：模型要求 16 kHz，麦克风原始 44.1 kHz，必须重采样。
直接喂 44.1 kHz 不会报错，但识别结果全是乱码。

**② 录音用 `arecord` 而不是 PyAudio**：PyAudio 在该板子上偶发丢帧，
导致句首被削掉。

#### 2.4.3 VAD 参数与响应延迟

**端到端延迟 = 静音判定 + ASR 推理 + 意图解析。**

| 参数 | 原值 | 现值 | 效果 |
|---|---|---|---|
| `--silence` | 1.5 s | **0.9 s** | 说话结束后更快收尾 |
| `--max-time` | 3 s | **2 s** | 单句上限缩短 |

**实测：端到端从 4.4 s 降到 1.33 s。**

```
🗣 听到：葡萄 → 意图 grasp  (ASR 1.31s → 说完共 1.33s)
```

**风险与回退**：若出现指令被截断，把 `--silence` 改回 1.2、
`--max-time` 改回 3 即可，不需改代码。

### 2.5 具身抓取闭环（核心）

#### 2.5.1 为什么必须闭环

| | 回退路径（单帧快照） | **主路径（具身闭环）** |
|---|---|---|
| 视觉 | **拍照一次**，然后闭眼抓 | **3 fps 持续观测** |
| 判定 | 力控到目标就停 | **力 + 边缘 双模态** |
| 成功判据 | 力达到目标 | **A→B 到达 + 停稳** |
| 失败识别 | 事后发现滑移 | **当场判 脱落 / 夹空** |

**"夹住了 / 正在滑 / 已经掉了"是随时间演化的过程，只看一瞬间判断不出来。**

#### 2.5.2 三线程架构

| 线程 | 频率 | 职责 |
|---|---|---|
| **视觉线程** | 3 fps（133 ms/帧） | 连续取帧 → 颜色分割 → 轮廓 → 扁平度；七帧中值稳定器（空间门限 + 时间中值）后发布最新结果 |
| **主循环** | 10 Hz | 测力（0.35 s 窗中位数）→ 状态机 tick → 决定是否继续闭合 |
| **预览线程** | 3 fps | 复用视觉帧，画标注后 MJPEG 推流（约 3 % CPU） |

**为什么视觉单独开线程**：一次检测 133 ms，若放在主循环里，
20 Hz 的力采样会被卡住。分开后互不影响。
**代价**是需要加锁传递最新结果，且视觉频率受检测耗时限制。

#### 2.5.3 状态机：五个状态 + 两种失败

| 状态 | 判据 | 确认拍数 |
|---|---|---|
| 采基线 | 张开、未接触，实测扁平度基线 | 4 个样本 |
| **闭合中** | 力 < 目标，脉宽逐步减小（每拍 2~4 µs） | — |
| **接触到** | 力峰值 > 0.05 N **且** 扁平度涨幅 ≥ 0.015 | 连续 2 拍 |
| **夹到了** | 力峰值 ≥ 0.50 N **且** 扁平度涨幅 ≥ 0.015 | 连续 3 拍（锁存） |
| **已移到B** | 距 B 点 ≤ 容差 **且** 停稳 **且** 仍被夹持 | 连续 3 拍 |
| **脱落** | 扁平度涨幅回落 **且** 力也低 / 力骤降 / 葡萄消失 | 连续 4~5 拍 |
| **夹空** | 脉宽到下限 **且** 扁平度从未上升 | 连续 5 拍 |

**所有判据用"历史峰值 + 连续 N 拍确认"**，
因为力和扁平度都会"冲高后回落"（实测力从 1.87 N 掉到 0.5 N 以下）。
用当前值会因回落而永远判不出来。

#### 2.5.4 A→B 判定：预学 B 点 + 停稳

**"移动到 B"不能只判"位移够大"** —— 位移分不出"到了 B"和"路过 B"。

```bash
# 一次性：把葡萄放到目标位置，按回车记录
sudo python3 apps/embodied_grasp.py --learn-b
```

**存成画面比例（不是绝对像素），换分辨率不失效：**

```json
{"x_norm": 0.52235, "y_norm": 0.58447, "tol_px": 80,
 "frame_w": 1920, "frame_h": 1080}
```

**判定条件：**

```
已移到B = ① 质心距 B 点 ≤ 容差
         AND ② 连续 3 拍质心移动 < 8 px（真的停稳了，不是路过）
         AND ③ 力 ≥ 0.15 N 且仍在被夹持
```

**没学过 B 点时会自动退回"位移 ≥ 200 px"，不报错。**

#### 2.5.5 实测状态序列

```
[ 3.6s] 闭合中   力  +0.05N  扁平度 0.141  宽度 241px  基线 0.1469
[10.3s] 接触到   力  +1.60N  扁平度 0.162  ← 力峰值 2.04N + 涨幅 +0.0155
[11.3s] 夹到了   力  +2.20N  扁平度 0.180  ← 力峰值 2.20N + 涨幅 +0.0326
[25.4s] 已移到B  距 B 点 35px ≤ 80px，停稳 3 拍，力 1.18N
结论：✅ 已移到 B
```

#### 2.5.6 网页实时预览


### 2.6 产品化与人机交互

#### 2.6.1 常听模式

开发阶段所有命令都从电脑发出，但**交付时终端必须独立运行**。

`product_mode.py` 实现常听循环：持续监听、检测到人声即录音识别、
识别到意图就执行对应动作，然后回到待命。

**关键技术点**：ASR 推理约 2.3 s，摄像头拍照约 1.0 s，
两者互不依赖 —— 用线程池并行，可省约 1 s。

#### 2.6.2 无屏幕的状态反馈：夹爪手势

**交付形态没有显示器，人怎么知道它准备好了？**

设计了三套手势（复用同一个舵机，不增加硬件）：

| 手势 | 含义 | 动作 |
|---|---|---|
| **招手** | 已就绪，可以下指令 | 张开/半闭 两下 |
| **点头** | 任务完成 | 上下两次 |
| **摆手** | 任务失败 | 左右两次 |

**招手会周期性重复**（每 15 秒一次，共 2 次），因为人不可能一直盯着它。

#### 2.6.3 开机自启与断电恢复

用 systemd 服务：

```
WantedBy=multi-user.target    开机自启
Restart=always                崩溃 3 s 后自动重启
显式设置 HOME                  否则 ASR 模型路径会指错
```

**断电重启后服务自动拉起，重新进入待命状态。**
这是明确验证过的能力（见附录 C 测试报告）。

### 2.7 性能优化

#### 2.7.1 延迟拆解（实测）

| 阶段 | 耗时 | 优化情况 |
|---|---|---|
| 静音等待（VAD 判定句尾） | 1.5 s → **0.9 s** | ✅ 已优化 |
| ASR 推理 | 1.37 s | ❌ 内存瓶颈，NPU 无收益 |
| 摄像头拍照 | ~1.0 s | ✅ 已由具身流程的连续流消除 |
| 视觉识别（单帧） | 0.43 s | ✅ 已由连续流分摊 |
| 力控抓取 | 21.8 s | ✅ 自适应步长（原 27 s） |

**"说完话 → 夹爪开始动"：4.4 s → 1.33 s。**

#### 2.7.2 视觉处理的三级加速

| 手段 | 效果 |
|---|---|
| **两级检测**（0.25 缩略图粗定位 + 全分辨率精测） | **3087 ms → 133 ms** |
| **ROI 跟随**（质心平滑跟踪，丢失 3 拍后清除） | 单帧耗时降约 3 倍 |
| **形态学只做开运算**（切断细连线，不做闭运算） | 省约 40 % |

#### 2.7.3 散热与资源

| 项 | 实测 |
|---|---|
| 视觉 3 fps 时板子温度 | 58~64 °C |
| 视觉 16 fps 连续推流 | **曾烧到 79 °C（事故）** |
| CPU 占用（具身流程） | 约 40 % |
| 网页预览额外开销 | 约 3 % CPU |

**结论：3 fps 是在"实时性、准确性、散热"三者之间的实测平衡点。**

#### 2.7.4 关于 AI 核占用的取舍（诚实说明）

| 流程 | AI 核 | CPU | 能力 |
|---|---|---|---|
| 回退路径 + `--npu` | **91 %** | 50 % | 抓取（无 A→B 判定） |
| 主路径（具身闭环） | **≈ 0 %** | 40 % | 实时监控 + 双模态 + A→B |

**原因**：AI 核占用 ≈ 帧率 × 单帧推理时间（YOLOv8n 约 20 ms），
而 CPU 上的边缘精测是 133 ms/帧。提高帧率会让 CPU 超过 60 %。

**所以具身流程选择不使用 NPU，把 CPU 预算全部留给边缘精测，
以保证判定实时性。这是有意识的取舍，不是漏用算力。**

### 2.8 异常处理

**所有失败都带具体原因，不是笼统的"失败"：**

| 异常 | 系统响应 |
|---|---|
| **夹空**（两指间没有葡萄） | 判"夹空"：脉宽到下限 + 扁平度从未上升 |
| **脱落**（夹住后掉了） | 判"脱落"：扁平度回落 / 力骤降 / 葡萄消失 |
| **葡萄被画面边缘切掉** | 拒绝测量，报"被画面某边缘切掉 → 请调整机位" |
| **视觉锁到黑色传感器块** | 颜色优先级（绿>紫>黑）自动纠正 |
| 语音要求的目标视觉没看到 | 拒绝执行，避免盲夹 |
| 语音与视觉不一致 | 拒绝执行，打印双方结果 |
| 夹持力超硬上限 | 立即松开 |
| 舵机堵转 | 判为"已夹住"（若力够）或报硬件极限 |
| 相机故障 | 捕获异常，不退出，继续待命 |
| **中途断电** | systemd `Restart=always`，上电自动恢复待命 |

**真实报错样例：**

```
葡萄被画面「左、上」边缘切掉，轮廓形状不可信（扁平度会虚高）→ 请调整机位
脉宽已到下限 750µs，且扁平度从未上升 → 两指之间没有葡萄
扁平度涨幅回落到 +0.003（<0.008）且力只有 0.02N，连续 4 拍 → 已不再被挤压，葡萄脱落
```

## 五、应用价值与市场潜力

### 5.1 直接可迁移的场景

| 场景 | 本项目的哪部分直接可用 |
|---|---|
| **果蔬采摘 / 分拣** | "力+视觉"判断成熟度与夹持状态的方法 |
| **实验室自动化** | 常听模式 + 无屏幕手势反馈的交互形态 |
| **轻工业装配** | 双模态判定"是否夹到"的思路 |
| **教育机器人** | 全本地、可复现、成本低的边缘 AI 教学平台 |

### 5.2 方法的通用性

**本项目最有价值的部分不是"抓葡萄"，而是两个可迁移的工程结论：**

**① "两个独立物理量同时变化才可信"**

任何"判断某件事是否真的发生了"的场景都适用：
力 + 边缘（本项目）、压力 + 温度（工业）、电流 + 振动（电机诊断）。
**单模态判断极易被环境干扰欺骗，双模态逻辑与能显著降低误判。**

**② "成功"要用可观测的空间证据定义**

"夹住了"是内部状态，"从 A 移到 B"是可观测事实。
**用后者定义成功，系统的报告才可信。**

### 5.3 成本与部署优势

| 项 | 本项目 |
|---|---|
| 主控 | MUSE Pi Pro（K1），2 TOPS |
| 总硬件成本 | 开发板 + 摄像头 + 麦克风 + 舵机 + 2× 力传感器 + 3D 打印夹爪 |
| AI 模型体积 | 1.9 MB（可离线部署，无需云端） |
| 部署方式 | 一条 systemd 服务，插电即用 |

**全本地推理意味着**：无网络依赖、无隐私风险、响应延迟可控 ——
这是边缘 AI 相对云端的核心优势，也是本项目的立足点。

### 5.4 局限与诚实评估

| 局限 | 影响 | 改进方向 |
|---|---|---|
| 力控精度有限（目标 1.0 N，实际 2.0~2.2 N） | 无法做精细力控任务 | 换带力矩反馈的执行器 |
| 视觉 3 fps | 快动作可能漏判 | NPU 加速 + 降 CPU 占用 |
| 依赖预学 B 点 | 摄像头移动后需重学 | 用桌面标记做自动标定 |
| 不判"夹得多紧" | 无法做"轻拿轻放"分级 | 需要更高精度的力反馈 |
| 未使用 LLM | 意图解析是规则匹配 | 任务复杂度提升时再引入 |

### 附录 D 已知局限汇总

| 局限 | 具体表现 | 原因 |
|---|---|---|
| 力控精度有限 | 目标 1.0 N，实际稳定在 2.0~2.2 N | 位置控制舵机在负载下持续 creep |
| "滑移"判据不可靠 | 实测两次误报（+30~32 px） | 可见宽度同时受夹紧程度和距离影响 |
| 视觉帧率受限 | 3 fps | CPU 边缘精测 133 ms/帧 |
| A→B 依赖预学 | 摄像头一动就失效 | B 点是画面坐标，不感知真实三维位置 |
| 不判"夹得多紧" | 只判"夹到/没夹到" | 视觉测不准（重夹时被遮挡），力又不稳定 |
| 未使用 LLM | 意图解析是规则匹配 | 指令空间极小，LLM 会显著增加延迟 |
