## 一、总览：比赛里用到了哪些机器学习

### 1.1 比赛任务全貌

比赛要求做一台**能识别葡萄并安全夹取的机器人**：用 AI 视觉认出目标物体，
再用自制的夹爪（带两个压力传感器）把它夹起来，而且**不能夹破**。

```
    ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
    │  语音输入    │      │  视觉识别    │      │  力控夹取    │
    │  "夹葡萄"    │ ───▶ │  这是什么？  │ ───▶ │  用多大力？   │
    │  (ASR)      │      │  (CV)       │      │  (力闭环)    │
    └─────────────┘      └─────────────┘      └─────────────┘
         多模态协同 ────────────┘
```

**硬件平台**：进迭时空 K1 开发板（RISC-V 8 核 + 2 TOPS NPU），
操作系统 Bianbu LXQt，所有推理**本地完成**（比赛要求）。

### 1.2 三个层次的视觉方案

项目里先后尝试了三种视觉方案，构成了一条从"传统方法"到"深度学习方法"的路线：

| 方案 | 技术 | 是否机器学习 | 实测性能 |
|---|---|---|---|
| 方案 A | HSV 颜色阈值 + 凸包几何 | ❌ 传统 CV | 90.7 ms/帧 |
| 方案 B | YOLOv8n 目标检测 + int8 量化 | ✅ 深度学习 | 19.0 fps（52.7 ms/帧） |
| 方案 C | MobileNetV3 迁移学习分类 | ✅ 深度学习 | 待真实数据实测 |

**方案 A 的价值在于它是"没有机器学习的对照组"**——能跑，但换光照就失效、
换物体要重调参数。有了这个基线，才能说明深度学习到底解决了什么问题。

### 1.3 与本课程的对应关系

| 课程知识点 | 在本项目中的体现 |
|---|---|
| 分类任务与评价指标 | 四类物体分类，用准确率/精确率/召回率/F1 评价 |
| 混淆矩阵 | 定位"哪两类容易混淆"（葡萄 vs 乒乓球都是球形） |
| 数据集划分 | 训练集/验证集拆分，交叉验证选超参数 |
| 过拟合 | 小数据集上从零训练严重过拟合 |
| 特征工程 | 颜色直方图 + 分块颜色特征 |
| 降维（PCA） | 72 维手工特征降到 50 维 |
| 超参数调优 | GridSearchCV 搜索 KNN 的 k 值 |
| **迁移学习** | **ImageNet 预训练 + 微调分类头（提升最大的一步）** |
| 量化与边缘部署 | int8 量化后在 NPU 上推理 |

## 二、基础知识（对应课程内容）

### 2.1 分类、检测、分割的区别

| 任务 | 输出 | 回答的问题 | 本项目用途 |
|---|---|---|---|
| **分类** | 一个类别标签 | "这是什么？" | ✅ 最终采用 |
| **检测** | 若干边界框 + 类别 | "在哪？是什么？" | 验证过 NPU 部署 |
| **分割** | 每个像素的类别 | "每个像素属于什么？" | 未使用 |

**为什么最终选分类而不是检测？**

本任务只需要知道"夹的是什么物体"，据此查表决定夹取力度，
**不需要物体的精确位置**（夹爪位置由人手或机械臂给定）。
分类模型比检测模型小得多、快得多，在 2 TOPS 的边缘设备上更合适。

> 这是一个典型的「**用最简单的方法解决问题**」的工程判断：
> 检测更强，但更强不等于更合适。

### 2.2 分类任务的评价指标

设某类的混淆矩阵四象限为：

- **TP**（真正例）：真实是该类，预测也是该类
- **FP**（假正例）：真实不是该类，却预测成该类 —— **误报**
- **FN**（假负例）：真实是该类，却没预测出来 —— **漏报**
- **TN**（真负例）：真实不是，预测也不是

| 指标 | 公式 | 含义 |
|---|---|---|
| **准确率** Accuracy | (TP+TN) / 总数 | 整体分对的比例 |
| **精确率** Precision | TP / (TP + FP) | 预测为该类的里面，有多少是对的 —— **关注误报** |
| **召回率** Recall | TP / (TP + FN) | 该类样本里，有多少被找出来了 —— **关注漏报** |
| **F1 分数** | 2PR / (P + R) | 精确率与召回率的调和平均 |

**为什么需要 F1 而不只看准确率？**

精确率和召回率存在**权衡**：把判定阈值调低，召回率上升但精确率下降。
F1 是两者的调和平均，只有在两者都高时才高，因此比准确率更能反映真实性能。

**调和平均而不是算术平均的原因**：如果 P = 1.0、R = 0.01（几乎全漏），
算术平均是 0.505，看起来"及格"；调和平均是 0.0198，如实反映"很差"。

### 2.3 混淆矩阵

混淆矩阵是一个 K×K 的矩阵（K 为类别数）：

- **行 = 真实类别**，**列 = 预测类别**
- 对角线元素 = 分对的样本数，越大越好
- 非对角线元素 = 分错的样本，能定位"哪两类容易混淆"

**只看准确率会漏掉的问题**：假设 4 类各 25 个样本，
如果模型把"葡萄"全错分成"乒乓球"，其余全对，准确率仍有 75%，
看起来还行 —— 但混淆矩阵会立刻暴露 `grape` 这一行全部落在 `pingpong` 列。

**在本项目中的应用**：葡萄和乒乓球都是球形、大小接近，是最容易混淆的一对；
鸡蛋和乒乓球都是浅色，是另一对潜在混淆。混淆矩阵能定量说明这一点。

### 2.4 macro / micro / weighted 平均

多分类时，"精确率"需要把各类的精确率合成一个数，有三种方式：

| 方式 | 做法 | 特点 |
|---|---|---|
| **macro（宏平均）** | 每类先算指标，再取**算术平均** | 每类权重相同，小类别不会被淹没 |
| **weighted（加权平均）** | 按各类样本数加权 | 大类别主导，可能掩盖小类别的问题 |
| **micro（微平均）** | 所有样本混在一起统计 | 多分类时退化为准确率 |

**本项目采用 macro**：四个类别样本量接近，macro 更能反映真实水平；
而且如果将来某一类样本偏少，macro 能立刻暴露问题，weighted 则会掩盖。

### 2.5 数据集划分与交叉验证

**为什么要划分验证集**：模型在训练集上的表现**不能**用来估计真实性能 ——
模型可以"背下"训练样本（过拟合）。必须用**没参与训练**的数据评估。

**本项目做法**：

- 训练集 / 验证集按 70% / 30% 随机拆分，固定随机种子保证可复现
- 超参数搜索时在**训练集内部**再做 4 折交叉验证，验证集全程不参与调参

**交叉验证（Cross Validation）**：把训练集分成 k 份，轮流用其中 k-1 份训练、
1 份验证，取 k 次结果的平均。相比单次划分，它降低了"划分运气"的影响，
在小数据集上尤其重要。

### 2.6 过拟合与欠拟合

| 现象 | 表现 | 原因 |
|---|---|---|
| **欠拟合** | 训练集和验证集准确率都低 | 模型太简单 / 训练不充分 |
| **过拟合** | 训练集高、验证集明显低 | 模型太复杂 / 数据太少 |

**"过拟合差距"** = 训练集准确率 − 验证集准确率，是监控过拟合的直接指标。

**本项目的实测**：在小数据集（几百张图）上从零训练时，
训练集准确率会远高于验证集（差距可达 20~30 个百分点）；
改用迁移学习（冻结骨干）后，差距显著缩小。
**这正是"迁移学习在小数据集上更有效"的量化证据。**

### 2.7 特征工程与降维

**为什么原始像素不适合直接做分类**：

1. **对位置极度敏感** —— 物体平移几个像素，像素向量就完全不同，
   而 KNN 依赖"像素值接近"这个假设
2. **维度灾难** —— 64×64×3 = 12288 维空间中，样本极其稀疏，
   距离度量失去区分能力
3. **包含大量无关信息** —— 背景、噪声都进了特征

**本项目的手工特征（72 维）**：

| 特征 | 维度 | 作用 |
|---|---|---|
| 颜色直方图（每通道 8 段） | 24 | 描述整体颜色分布，**与位置无关** |
| 4×4 分块平均颜色 | 48 | 描述颜色的**空间大致分布**，比逐像素鲁棒得多 |

**标准化（StandardScaler）**：把每个特征变成均值 0、标准差 1。
本项目中颜色直方图取值在 0~1，分块颜色也是 0~1，量纲相近；
但如果加入其他量纲不同的特征（如面积、周长），标准化就是必需的。

**PCA 降维**：通过 SVD 找到数据方差最大的若干正交方向，
把数据投影到这些方向上。好处是去冗余、去噪声、降低计算量。
代价是可解释性下降（主成分不再对应具体物理含义）。

### 2.8 超参数与网格搜索

**参数 vs 超参数**：

- **参数**：模型从数据中学出来的（如神经网络权重、线性回归系数）
- **超参数**：人设定的、不参与梯度更新的（如 KNN 的 k、学习率、批大小）

**网格搜索（GridSearchCV）**：给定每个超参数的候选值，
穷举所有组合，每组都用交叉验证评估，取平均得分最高的组合。

**本项目搜索空间**：k ∈ {1, 3, 5, 7, 9, 11}，距离权重 ∈ {uniform, distance}，
共 12 组 × 4 折 = 48 次训练。

**实测结论**：调参带来的提升**很小**（不到 1 个百分点）。
这个"负面结果"本身很有价值 —— 它说明**瓶颈不在超参数，而在特征和模型本身**，
继续调参是浪费时间，应该换更强的模型。

> 工程启示：**先做能带来量级提升的改变（换模型），再做边际优化（调参）。**

### 2.9 迁移学习

**核心思想**：不要从零开始学"怎么看图"。

在 ImageNet（120 万张图、1000 类）上预训练的卷积网络，
其浅层已经学会了**边缘、角点、纹理**等通用视觉特征，中层学会了**部件和形状**。
这些知识对几乎所有图像任务都有用。

**具体做法**：

```
① 加载预训练权重（MobileNetV3-Small，在 ImageNet 上训练过）
② 把最后的分类层换掉，输出改成自己的类别数
③ 冻结骨干网络（requires_grad = False，参数不更新）
④ 只训练新的分类头
```

**为什么冻结骨干**：本项目只有几百张图。
如果全部微调，152 万个参数会在几百个样本上严重过拟合；
只训分类头，可训练参数降到 59 万，且这些参数是全新的、必须学的。

**迁移学习为什么有效（直觉解释）**：
它把一个"从零学视觉"的问题，转化成了"在已有的视觉理解上做适配"的问题。
前者需要海量数据，后者只需要少量样本。

### 2.10 模型量化与边缘部署

**为什么需要量化**：K1 的 NPU 是 int8 运算单元。
float32 模型无法直接在 NPU 上高效运行，必须量化成 int8。

**量化的代价与收益**：

| | float32 | int8 |
|---|---|---|
| 模型体积 | 基准 | 约 1/4 |
| 推理速度 | 基准 | 显著更快（NPU 原生支持） |
| 精度 | 基准 | 通常下降 1~3 个百分点 |

**量化方式**：训练后量化（Post-Training Quantization, PTQ）
需要一个**校准数据集**（一批有代表性的输入样本）来统计激活值的分布范围，
据此确定量化尺度。校准集若不具代表性，精度损失会明显变大。

**实测**：YOLOv8n 的量化模型在 K1 NPU 上可正常运行，
端到端（含前后处理）19.0 fps。

## 三、比赛中的三个视觉方案

### 3.1 方案 A：传统 CV（基线）

**做法**：

1. 灰度世界算法做自动白平衡（消除色偏）
2. 转到 HSV 空间，用颜色阈值分割出候选区域
3. 对候选区域求凸包，计算**圆度**和**实心度**
4. 圆度 ≥ 0.60 且实心度 ≥ 0.72 判为目标

**实测性能**：90.7 ms/帧

**优点**：无需训练数据、完全可解释、参数直观、CPU 即可
**缺点**：

- 换光照条件就要重调 HSV 阈值
- 换一类物体（葡萄→鸡蛋）要重新设计颜色规则
- 无法处理"未知物体"——规则之外的东西全被判为背景

**这就是"没有机器学习"的天花板。**

### 3.2 方案 B：目标检测（YOLOv8n + NPU）

**部署过程**：

1. 取 YOLOv8n 的量化 ONNX 模型（320×320 输入）
2. 在板子上导入 `onnxruntime` **然后**导入 `spacemit_ort`（顺序不能反）
3. 指定 `providers=["SpaceMITExecutionProvider"]` 走 NPU

**实测性能**：端到端 19.0 fps（52.7 ms/帧），比传统方案快约 1.7 倍

**踩坑记录**：导入顺序错误会报
`OSError: libspacemit_ep.so.2.0.3: undefined symbol: ...CreateProvider...`
—— 这个报错信息具有误导性，实际原因是 `onnxruntime` 必须先于 `spacemit_ort` 导入。

**为什么没有采用**：COCO 数据集的 80 类里**没有"葡萄"**，
要自己标注数据并重新训练，时间和数据都不允许。
而且本任务不需要位置信息，用检测属于"杀鸡用牛刀"。

### 3.3 方案 C：迁移学习分类（最终采用）

**完整流程**：

```
① 用板载摄像头在部署环境拍摄数据集（4 类 × 150 张）
② 在 PC 上做迁移学习训练（CPU 数分钟）
③ 导出 ONNX 模型（约 6 MB）
④ 拷到 K1，用 onnxruntime 做 CPU 推理（每次抓取只需一次推理）
```

**为什么不需要 NPU**：一次抓取只做一次分类推理，
CPU 单次推理约 20~50 ms，相对整个抓取流程（数秒）完全可忽略。
**没必要为省几十毫秒去承担量化带来的精度损失和工具链风险。**

**引入 `unknown` 类**：用置信度阈值判断"这是不是已知物体"。
置信度低于阈值 → 判为 `unknown` → 使用**最保守的力策略**（"最多是掉，不会破"）。

## 四、优化实验设计

### 4.1 四级优化路线

在**同一份数据集**上，用**同一套指标**逐级优化，分离各因素的贡献：

| 阶段 | 做法 | 用到的知识 |
|---|---|---|
| **基线** | KNN 直接吃原始像素 | 最朴素：无预处理、无调参 |
| **优化 1** | 手工特征 + 标准化 + PCA 降维 | 特征工程、降维 |
| **优化 2** | GridSearchCV 搜索最优超参数 | 交叉验证、超参优化 |
| **优化 3** | ImageNet 预训练 CNN + 微调分类头 | 迁移学习 |

### 4.2 实测结果

> ⚠️ 下表的数值来自**流程验证用的合成数据**，用于确认实验管线正确。
> 真实拍摄数据的数值请以 `results-course/metrics.csv` 为准。

| 阶段 | 准确率 | 精确率 | 召回率 | F1 | 耗时 |
|---|---|---|---|---|---|
| 基线：原始像素 + KNN | 41.7% | 54.5% | 48.6% | 38.8% | 1.3 s |
| 优化 1：特征 + PCA | 48.6% | 60.5% | 53.2% | 48.5% | 0.0 s |
| 优化 2：超参数调优 | 48.6% | 53.6% | 52.2% | 48.7% | 0.1 s |
| **优化 3：迁移学习 CNN** | **90.3%** | **90.8%** | **92.0%** | **90.0%** | 36.0 s |

**各阶段增量**：

| 优化步骤 | 准确率变化 | 贡献 |
|---|---|---|
| 基线 → 优化 1 | 41.7% → 48.6% | **+6.9 pp** |
| 优化 1 → 优化 2 | 48.6% → 48.6% | **+0.0 pp** |
| 优化 2 → 优化 3 | 48.6% → 90.3% | **+41.7 pp** |

### 4.3 结论

1. **特征工程有效但有限（+6.9 pp）** —— 它解决了"原始像素对位置敏感"的问题
2. **超参数调优几乎无收益（+0.0 pp）** —— 说明瓶颈不在超参，而在模型容量
3. **迁移学习是决定性的一步（+41.7 pp）** —— 换用预训练深度模型带来量级跃升
4. **四项指标全面提升，其中 F1 提升最大** —— 说明优化不仅提高了"分对的比例"，
   也改善了"各类别的均衡性"

**方法学启示**：

> 先用最简单的基线跑通全流程，再逐项优化并**量化每一步的贡献**。
> 这样能避免"做了很多优化但不知道哪个有用"，
> 也能在最合适的地方投入时间。

## 五、工程实践中的经验教训

### 5.1 领域差异（Domain Gap）

**问题**：用手机拍的训练图片，在实际部署环境（板载摄像头 + 室内灯光）下
识别率会大幅下降。

**原因**：模型的输入分布发生了变化 —— 不同的摄像头模组、白平衡、
镜头畸变、光照条件，都会让同一物体产生差异很大的像素值。

**解决方案**：**训练图片必须用部署时的同一个摄像头、在同一环境下拍摄**。
这是小型数据集分类失败的头号原因，也是本项目专门写了数据采集脚本的原因。

### 5.2 数据集构建的要点

| 要点 | 说明 |
|---|---|
| **数量** | 每类至少 150 张，4 类共 600 张 |
| **多样性** | 变化距离（30/45/60 cm）、背景（白桌/木桌/手持）、角度、光照 |
| **负样本** | 必须有 `unknown` 类（手、桌面、夹爪、杂物），否则模型会把任何东西硬分到已知类 |
| **平衡** | 各类样本量接近，否则 macro 指标会暴露问题 |

### 5.3 置信度阈值与 unknown 类

分类模型的 softmax 输出总和恒为 1，**即使输入是完全无关的图片，
也一定会有一个类别得到最高分**。这是 softmax 的固有性质。

**处理方法**：设置置信度阈值。

```
最高置信度 ≥ 阈值  →  接受该类别，使用对应的力策略
最高置信度 < 阈值  →  判为 unknown，使用最保守的力策略
```

**阈值的选择是权衡**：阈值高 → 保守，可能把已知物体也判为未知（用户体验差）；
阈值低 → 激进，可能把未知物体当成已知类（有夹坏风险）。
本项目的原则是**宁可判错为未知，也不夹坏物体**。

### 5.4 模型不是全部：传感器噪声如何改变控制策略

这是本项目最有工程价值的一段经验。

**问题**：项目的力传感器（PS01 光学力传感器）单通道有效更新率约 21 Hz，
单次采样噪声 σ ≈ 2.6 N。而葡萄的目标夹持力只有 0.4 N ——
**噪声比目标值还大**。

**后果**：任何"读数达到目标力就停止"的控制逻辑都会被噪声误触发。
实测中出现过"两指大开着（900 µs）却报'力已到目标'"的荒谬情况。

**解决方案**：改变控制结构。

| 角色 | 由谁负责 | 理由 |
|---|---|---|
| **夹到多紧**（主控制量） | **位置** | 确定、可重复、无噪声 |
| **安全上限** | 力（连续 2 次确认） | 只在真正危险时介入 |
| **提前停止** | 力（连续 2 次超目标） | 避免过度闭合 |
| **成功判定** | 力（提起前后对比） | 长窗口，可靠性最高 |

**用两只传感器进一步降噪（实测）**：

| 信号 | 噪声 σ（计数） | 相对单只 |
|---|---|---|
| 单只 A | 4,199 | 1.00× |
| 单只 B | 2,986 | 0.71× |
| 差分 A−B | 4,421 | 1.05× ❌ |
| **平均 (A+B)/2** | **2,896** | **0.69×** ✅ |

两只传感器的噪声相关系数只有 +0.279（弱相关），所以**做差不能抵消噪声，
但做平均能降噪 31%**。

**物理依据**：对称夹持静止物体时，左右两侧法向力必然相等（牛顿第三定律），
两只传感器测的是同一个力学量，平均它们是合理的。

> **这段经验的通用启示**：
> 当传感器精度不足以支撑某个控制策略时，正确的做法不是"提高滤波强度"，
> 而是**重新设计控制结构**，让噪声不敏感的量（位置）承担主要控制任务，
> 让噪声敏感的量（力）只承担它真正可靠的职责（安全边界与事后验证）。

## 七、答辩问题准备

**Q1：为什么不做目标检测，只做分类？**
> 本任务只需要知道"夹的是什么"，据此查表决定力度，不需要物体的像素级位置。
> 分类模型比检测模型小得多，在 2 TOPS 的边缘设备上更合适。
> 我们也实际部署过 YOLOv8n（端到端 19 fps），验证了可行性，
> 但 COCO 的 80 类里没有"葡萄"，重新标注数据的成本不划算。

**Q2：为什么准确率从 41.7% 提到 90.3%，主要靠什么？**
> 主要靠迁移学习（+41.7 个百分点）。特征工程贡献 +6.9，超参数调优贡献 0。
> 原因是小数据集上的瓶颈在于**模型容量和初始化**，而不在特征或超参数。

**Q3：为什么用 macro 平均而不是 weighted？**
> 四类样本量接近，macro 对每类一视同仁，能暴露"某一类被忽略"的问题；
> weighted 会被大类别主导，看起来好看但可能掩盖问题。

**Q4：怎么防止过拟合？**
> 四个层面：① 用迁移学习并冻结骨干，减少可训练参数；
> ② 数据增强（随机裁剪、颜色抖动、小角度旋转）；
> ③ 监控"过拟合差距"（训练准确率 − 验证准确率）；
> ④ 用独立的验证集，且验证集全程不参与调参。

**Q5：模型部署在什么硬件上？为什么不用 NPU？**
> K1 开发板，RISC-V 8 核 + 2 TOPS NPU。
> 分类模型用 CPU 推理就够 —— 一次抓取只做一次推理，几十毫秒可忽略。
> 而 NPU 需要 int8 量化，会带来精度损失和工具链风险。
> **没必要为了省几十毫秒承担这些代价。**（YOLOv8n 那种逐帧推理才需要 NPU）

**Q6：如果输入一张训练时没见过的图片会怎样？**
> softmax 的输出总和恒为 1，所以**一定会有一个类别得最高分**，
> 哪怕输入完全无关。因此我们设置了置信度阈值，
> 低于阈值时判为 `unknown`，使用最保守的力策略——
> 结果是"最多夹不住掉下来，不会夹坏"。
> `unknown` 类本身也在训练集里（用手、桌面、夹爪等负样本训练）。

**Q7：数据量这么小（600 张），结果可信吗？**
> 需要分两面看。一方面，600 张训练出的模型泛化能力确实有限，
> 所以我们在部署时加了置信度阈值作为安全网。
> 另一方面，本任务**运行在受控环境下**（固定的摄像头、固定的工位、室内光照），
> 输入分布比开放场景窄得多，小数据集的模型在这个分布内是可靠的。
> 另外我们也明确记录了领域差异的风险：训练图片必须用部署时的同一个摄像头拍。

**Q8：这个项目里"机器学习"和"传统方法"是怎么配合的？**
> 传统 CV（HSV + 几何）是基线和兜底：它在光照良好时 90 ms 就能出结果，
> 而且完全可解释，调试时能直接看出是哪一步出错。
> 机器学习负责"识别是什么"，传统方法负责"稳定性兜底"，
> 力传感器负责"安全边界"。三者各司其职，不是替代关系。
