## 一、PS01 光学力传感器通信逆向（核心成果）

### 1.1 背景

PS01 是「ams OSRAM AS7150 光学力传感 AFE + LED + 光电二极管 + MCU」构成的模块。
其 UART 协议由模块厂商自定义，**无公开文档**。

**现象**：厂商上位机 PS01Tool 能正常采集，但自写 pyserial 程序发送同样的字节
`gnst\r\n` 后，传感器完全无响应。

**关键困难**：
- 同一台电脑、同一个 CH340、同一个 COM 口、同一串字节
- PS01Tool 成功，pyserial 失败
- 串口抓包工具（Device Monitoring Studio）显示 TX 只有 `67 6E 73 74 0D 0A`

### 1.2 排查过程（关键节点）

| 序号 | 尝试 | 结果 |
|---|---|---|
| 1 | 命令变体（`gnst\r\n` / `gnst` / `gnst\r` / `gnst\n`） | 全部失败 |
| 2 | DTR/RTS 4 种组合 | 全部失败 |
| 3 | 发送延迟 0~5 秒 | 全部失败 |
| 4 | 重试 2/3/5 次 | 全部失败 |
| 5 | 先发 `gned` 再发 `gnst` | 失败 |
| 6 | 清空输入缓冲 | 失败 |
| 7 | 多线程持续读取（模仿 PS01Tool 的 SerialWorker） | 失败 |
| 8 | Windows 与 Linux 双平台 | 均失败 |
| 9 | 换用 K1 的 40Pin 硬件 UART（ttyS10，GPIO48/49） | 回环通过，接传感器仍失败 |
| 10 | 波特率扫描 8 个值 | 全部失败 |

### 1.3 突破口：反编译 PS01Tool

**步骤**：

1. 确认 PS01Tool.exe 是 PyInstaller 6.x 打包的 Python 3.9 程序
2. 安装 Python 3.9（Python 3.14 无法解析 3.9 的 marshal 格式）
3. `pip install pyinstxtractor-ng`
4. `py -3.9 -m pyinstxtractor_ng ps01tool.exe`
5. 得到 `PS01Tool.pyc`（35,261 字节）
6. **uncompyle6 / decompyle3 均不支持 Python 3.9.0（magic 3425）**
7. 改用 `xdis` 反汇编：
   `py -3.9 -m xdis.bin.pydisassemble PS01Tool.pyc`

### 1.4 根因：0xD4 唤醒字节

**反汇编 `send_text_command` 得到的字节码（关键片段）**：

```
124:  20 LOAD_FAST (self)
      22 LOAD_ATTR (serial)
      24 LOAD_METHOD (write)
      26 LOAD_GLOBAL (bytes)
      28 LOAD_CONST (212)          ← 212 = 0xD4
      30 BUILD_LIST 1
      32 CALL_FUNCTION (1 positional)
      34 CALL_METHOD (1 positional)
      36 POP_TOP

125:  38 LOAD_FAST (self)
      40 LOAD_ATTR (serial)
      42 LOAD_METHOD (write)
      44 LOAD_FAST (cmd)
      46 LOAD_CONST ("\r\n")
      48 BINARY_ADD
      50 LOAD_METHOD (encode)
      52 CALL_METHOD (0 positional)
      54 CALL_METHOD (1 positional)
      56 POP_TOP

126:  58 LOAD_GLOBAL (time)
      60 LOAD_METHOD (sleep)
      62 LOAD_CONST (0.02)
      64 CALL_METHOD (1 positional)
      66 POP_TOP
```

**还原成 Python 源码**：

```python
def send_text_command(self, cmd):
    if not (self.serial and self.serial.is_open):
        return False
    try:
        self.serial.write(bytes([212]))              # 0xD4 唤醒字节
        self.serial.write((cmd + "\r\n").encode())   # 实际命令
        time.sleep(0.02)
        return True
    except Exception as e:
        self.error_signal.emit(f"发送命令失败: {e}")
        return False
```

**结论**：

> **PS01Tool 每次发命令都是 `0xD4` + `cmd` + `\r\n`，共 7 字节。**
> **`0xD4` 是传感器固件要求的「唤醒/同步字节」，缺失时整包被丢弃。**

**为什么抓包没发现**：

DMS 抓包工具把 `0xD4` 当成控制字符（非可打印 ASCII）过滤了，
只记录了后面的 `67 6E 73 74 0D 0A`（`gnst\r\n`），导致长期误判。

### 1.5 验证结果

**发送 `D4 67 6E 73 74 0D 0A` 后**：

```
[1] 读到 51 行；✅ 收到初始化完成信号
[2] ✅ 收到回显：~measurement started~
[3] PD1= 681436 PD2= 708392 PD3= 691858   [135.1 Hz]

统计: {'samples': 508, 'raw_lines': 1644,
       'parse_errors': 0, 'status_messages': 0}
```

**与 PS01Tool 的波形数值一致**（PD1≈682k、PD2≈708k、PD3≈691k）。

### 1.6 经验总结（可写入技术文档）

1. **抓包工具会过滤控制字符** —— 逆向协议时不能只依赖抓包工具，必须多手段交叉验证
2. **反编译是终极手段** —— 当黑盒行为无法用抓包解释时，反编译上位机是决定性方法
3. **Python 版本必须匹配** —— PyInstaller 打包的程序要用对应版本的 Python 反编译
4. **uncompyle6/decompyle3 对 3.9.0 支持不完整** —— 需要 `xdis` 反汇编兜底

## 二、K1 (MUSE Pi Pro) 硬件排查经验

### 2.1 UART 资源地图

| 设备节点 | 硬件地址 | 说明 | 引脚 |
|---|---|---|---|
| `/dev/ttyS0` | `d4017000.serial` | 主 SoC uart0 | PAD 68/69（40Pin 脚 8/10） |
| `/dev/ttyS2` | `d4017100.uart` | uart2 | PAD 21/22（不在 40Pin） |
| `/dev/ttyS10` | `c0881000.r_uart0` | **RCPU uart0** | GPIO 48/49（40Pin 脚 35/33） |

### 2.2 关键发现：RCPU uart0 被固件占用

**dmesg**：

```
pinctrl-single d401e000.pinctrl: pin PIN48 already requested by c088c000.rcpu_rproc;
                                 cannot claim for c0881000.r_uart0
pxa2xx-ruart0 c0881000.r_uart0: Error applying setting, reverse things back
```

**说明**：`pinctrl_rcpu_grp` 已由 `rcpu_rproc`（RCPU 远程核固件 esos.elf）应用，
GPIO48/49 被复用为 UART，`/dev/ttyS10` 可以收发。

### 2.3 PADCONF 寄存器读取方法

**K1 的 pinctrl 基址 `0xd401e000`，每个 PAD 占 4 字节：**

```bash
# 读 GPIO48 的 PADCONF
sudo busybox devmem 0xd401e0c0
# 结果: 0x0000C441
#   0xC441 = 0xC440(配置位) | 0x1(mux=1，即 UART 功能)
```

**注意**：`/dev/mem` 不能用 Python mmap 直接读（CONFIG_STRICT_DEVMEM 限制），
但 `busybox devmem` 可以。

### 2.4 设备树修改实验（失败但有价值）

**尝试**：给 `r_uart0` 节点加 `pinctrl-0 = <&pinctrl_rcpu_grp>`

**结果**：与 `rcpu_rproc` 冲突，`ttyS10` 消失

**结论**：不要给已经被 rcpu 占用的引脚加第二次 pinctrl。

**已回滚**：备份文件 `k1-x_MUSE-Pi-Pro.dtb.bak.*`

### 2.5 回环测试方法（无示波器时的替代验证）

```python
# 短接 UART 的 TX 和 RX，发数据看能否收回
ser.write(b"LOOPBACK_TEST\r\n")
data = ser.read(256)
# data 包含 "LOOPBACK_TEST" 说明 UART 收发正常
```

**作用**：能区分「UART 控制器问题」和「外部设备问题」。

## 三、最终可用的传感器通信方案

```
传感器 3V3  →  CH340 的 3V3
传感器 GND  →  CH340 的 GND
传感器 TXD  →  CH340 的 RXD
传感器 RXD  →  CH340 的 TXD
CH340 插 K1 的 USB 口
```

**启动命令**：`\xd4gnst\r\n`（7 字节）

**驱动脚本**：`scripts/ps01_driver.py`（默认命令已含 0xD4）

**性能**：115200 baud，约 135 Hz 三通道采样，0 解析错误。
