# 第一步：让 K1 MusePi Pro 跑起来（照着做就行）

目的：从"刚拿到板子"到"能用终端操作板子，并看到它的 GPIO/PWM/摄像头资源"。
做完这一步，你就有能力往下接舵机和传感器了。

预计用时：1~2 小时（含下载镜像）。

## 0. 先搞清楚你手上是什么

K1 MusePi Pro 的关键规格（来自官方资料）：

| 项目 | 参数 |
|---|---|
| 处理器 | SpacemiT K1 / M1，8 核 RISC-V，2.0 TOPS NPU |
| 内存 | 8GB 或 16GB LPDDR4X |
| 存储 | 64GB eMMC5.1 + Micro SD 卡槽 + M.2 M-Key(2230 NVMe) |
| 系统 | Bianbu OS（基于 Ubuntu 的官方发行版）、Ubuntu、OpenKylin、Deepin、Fedora |
| 扩展口 | **40Pin GPIO**、M.2 M-Key、miniPCIe |
| 摄像头 | 1 路 4-lane MIPI CSI（22pin FPC）+ 1 路 2-lane MIPI CSI（15pin FPC） |
| 网口 | RJ45 千兆 |
| USB | 4 路 USB3.0 Type-A + 1 路 USB2.0 Type-C(device) |
| 调试口 | UART 串口 TTL 调试口 |
| 供电 | USB-PD，支持 5V/3A、9V/3A、12V/3A |
| 按键 | 侧边 3 个按键（通常是 power / reset / recovery 之类） |

参考：[华秋社区 MUSE Pi Pro 介绍与系统测试](https://p.eda.cn/a-1399472862770757632)、
[进迭时空官方 K1 MUSE Pi Pro 页面](https://www.spacemit.com/community/development-kit/k1-muse-pi-pro)

## 1. 选一条进系统的路

三条路，按你的条件选一条。

### 路线 A：接显示器 + 键盘鼠标（最省事，推荐第一次用）

1. HDMI 接显示器，USB 口插键盘鼠标。
2. 接 USB-PD 电源（**用 12V/3A 或 9V/3A 的 PD 充电器，不要用 5V/1A 的老手机充电头**）。
3. 开机，进 Bianbu 桌面，按向导设置语言/用户名/密码。
4. 打开「设置 → 关于」确认系统信息正常。

### 路线 B：SSH 远程登录（后面开发主要用这条）

板子和你的电脑接到同一个路由器/同一个 WiFi 下，然后在板子的桌面上开终端：

```bash
# 在板子上执行
ip addr | grep "inet "        # 记下板子的 IP，比如 192.168.1.123
sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

然后在你的电脑上（Windows 用 PowerShell 就自带 ssh）：

```powershell
ssh 你的用户名@板子IP
```

参考：[华秋社区教程里的 SSH 登录部分](https://p.eda.cn/a-1399472862770757632)（他用的是 MobaXterm，其实系统自带的 ssh 命令也一样）

### 路线 C：UART 串口调试口（板子起不来时的救命通道）

板子附带 USB 转串口线就是为了这个。用串口工具（Windows 上用 MobaXterm / PuTTY / 或 `pip install pyserial-miniterm`）
连接，波特率通常是 **115200**，能看到开机日志和登录提示。

**这条路的真正价值**：如果哪天系统起不来、或者你改配置把网络弄坏了，
只有串口能救你。所以第一条路走通之后，建议顺手把串口也试一次。

## 2. 在板子上跑这 6 条命令，把结果记下来

这些命令是"体检"，它们的输出决定了后面怎么接线。

```bash
# ① 系统和内核
uname -a
cat /etc/os-release | head -3

# ② Python 环境
python3 -V
pip3 -V

# ③ 40Pin 上到底有哪些资源（最关键的一条）
ls /sys/class/pwm/            # 有没有 pwmchip0、pwmchip1...
ls /sys/class/gpio/           # 老式 GPIO 接口在不在
gpiodetect                    # libgpiod 能不能用（没装就 sudo apt install -y gpiod）
gpioinfo | head -50           # 每个 gpiochip 有多少线、叫什么名字

# ④ I2C / SPI 外设节点（后面接 ADC 用）
ls /dev/i2c-*
ls /dev/spidev*
i2cdetect -l                  # 需要 sudo apt install -y i2c-tools

# ⑤ 摄像头
v4l2-ctl --list-devices       # 需要 sudo apt install -y v4l-utils
ls /dev/video*

# ⑥ 温度/频率（确认板子健康）
cat /sys/class/thermal/thermal_zone0/temp
```

**把 ③④⑤ 的输出发给我**，我就能告诉你：
- 哪个物理引脚是 PWM（进而知道舵机信号线接哪一脚）
- 哪个 I2C 总线上能挂 ADS1115（压力传感器 ADC）
- OV5647 到底出的是 /dev/video0 还是别的编号

## 3. 装依赖（一条命令）

```bash
sudo apt update
sudo apt install -y python3-pip v4l-utils i2c-tools gpiod python3-opencv python3-numpy
```

说明：
- `v4l-utils` → 摄像头调试
- `i2c-tools` → I2C 调试（`i2cdetect`）
- `gpiod` → 新式 GPIO 工具（`gpioset`/`gpioget`）
- `python3-opencv` → 视觉（用 apt 版比 pip 版在 RISC-V 上更省心）

如果 `python3-opencv` 装不上或版本太老，再退回 pip：
```bash
pip3 install opencv-python-headless numpy
```

## 4. 验证 OV5647 出图

这一步单独做，因为它最容易卡住。

```bash
# 看看设备节点和它支持的分辨率/格式
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
```

抓一帧存成文件：

```bash
# 方法一：v4l2 直接抓 MJPEG
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1280,height=720,pixelformat=MJPG \
         --stream-mmap --stream-count=1 --stream-to=test.jpg
```

```bash
# 方法二：用 GStreamer（如果装了）
gst-launch-1.0 v4l2src device=/dev/video0 num-buffers=1 ! jpegenc ! filesink location=test.jpg
```

或者用 Python 抓（最贴近你后面要写的代码）：

```python
import cv2
cap = cv2.VideoCapture("/dev/video0", cv2.CAP_V4L2)
ok, frame = cap.read()
print("抓到帧:", ok, None if frame is None else frame.shape)
if ok:
    cv2.imwrite("test.jpg", frame)
cap.release()
```

把 `test.jpg` 拷到电脑上看（`scp 用户名@板子IP:~/test.jpg .`）。

### OV5647 常见的坑

| 现象 | 原因 / 对策 |
|---|---|
| 没有 /dev/video* | 排线没插到底、插反了。FPC 排线的金属触点方向要对着板子的触点 |
| 有节点但抓帧失败 | 换 MJPG，降分辨率到 640x480 先试 |
| 画面全黑或极暗 | OV5647 模组本身没有 ISP，自动曝光要靠平台侧。先用固定光照 + 手动设曝光 |
| 画面偏色 | 同上，手动设白平衡，或者接受固定光照环境 |
| `i2cdetect` 看不到 0x36 | 排线问题或者 sensor 驱动没加载。OV5647 的 I2C 地址就是 0x36 |

> 比赛现场光照可控，**最稳的方案是打个固定的小台灯**，别指望自动曝光。
> 这样 HSV 阈值也稳定，视觉部分会好做很多。

参考：[进迭时空 MIPI 相机使用及常见问题](https://www.spacemit.com/community/document/info?lang=zh&nodepath=software/SDK/bianbu/user_guide/LXQt/Camera_FAQ.md)（注意这个页面是 JS 渲染的，直接抓不到正文，需要在浏览器里看）

## 5. 搞明白 PWM（决定舵机信号接哪一脚）

Linux 上控制舵机的标准方式就是 PWM，路径是：

```
/sys/class/pwm/pwmchipN/pwmM/
    period        # 周期，单位纳秒。舵机用 50Hz = 20000000 ns
    duty_cycle    # 高电平时间，单位纳秒。舵机 0.5~2.5ms = 500000~2500000 ns
    enable        # 写 1 使能
```

手动试一次（**先别接舵机，用万用表或者示波器量**，没有的话就接舵机但让它空转）：

```bash
# 假设是 pwmchip0 的第 0 路
cd /sys/class/pwm/pwmchip0
echo 0 | sudo tee export          # 导出通道 0，之后会出现 pwm0/ 目录
cd pwm0
echo 20000000 | sudo tee period   # 20ms 周期 = 50Hz
echo 1500000  | sudo tee duty_cycle  # 1.5ms 脉宽 = 舵机中位
echo 1 | sudo tee enable          # 开始输出
```

观察舵机是否转到中位。然后：

```bash
echo 1000000 | sudo tee duty_cycle   # 1.0ms → 应该往一个方向转
echo 2000000 | sudo tee duty_cycle   # 2.0ms → 往另一个方向
echo 0 | sudo tee enable             # 停止输出（舵机卸力）
```

### 关键问题：MUSE Pi Pro 的 40Pin 上 PWM 需要先做 pinmux

K1 的引脚是多功能复用的。**默认状态下 `/sys/class/pwm/` 可能是空的**，
因为那些引脚当前被复用成了普通 GPIO 或别的功能。

你需要：
1. 确认 40Pin 上哪几个物理引脚能输出 PWM（这个要查 MUSE Pi Pro 的引脚定义表）
2. 把那个引脚复用成 PWM 功能（通过设备树 overlay 或者厂家提供的 pinmux 工具）

**这一步是板子专属的，我还没查到 MUSE Pi Pro 的确切引脚表**（官方文档站是 JS 渲染的，
抓不到正文）。所以：

- 请你在浏览器里打开 [Bianbu 引脚定义说明](https://bianbu.spacemit.com/brdk/Basic_applications/3.3_Pin_Applications/3.3.1_Pin_Definitions/)
  和 [MUSE Pi Pro 用户指南](https://www.spacemit.com/community/document/info?lang=zh&nodepath=hardware/eco/k1_muse_pi_pro/pi_pro_user_guide.md)，
  把 40Pin 那张引脚定义表**截图发给我**
- 或者直接跑第 2 步里的 `ls /sys/class/pwm/` 和 `gpioinfo`，把输出发我

拿到之后我立刻给你写死 `config.yaml` 里的 `servo.pwm_chip` / `pwm_channel`，
以及 pinmux 的具体命令。

### 如果 PWM 实在打不通，有个备选方案

**用一块 ESP32 专门管舵机和力采样，通过串口和 K1 通信。**

理由不只是"PWM 打不通"：
- 舵机 PID 需要 100~200Hz 的稳定控制周期，Linux 不是实时系统，Python 更不是
- 力采样 + PWM 输出都放在 MCU 上，时序稳定得多
- K1 只管"看到葡萄了，坐标在这里，去夹"这种高层决策

代价是多一块板子和一点串口协议。**如果你的时间紧张，这是个值得认真考虑的架构**，
而且工程上更专业（分工清晰）。这个方案我已经在代码里留了接口
（`config.yaml` 里的 `servo.driver: serial_bus`），需要时我再补实现。
