## 这是什么

一句话：**你说「葡萄」，机器识别、夹起来、搬到目标位置，全程没人碰它。**

```
   你：「葡萄」
        │
        ▼
  ┌──────────────────┐
  │ ASR（SenseVoice） │  本地推理，1.3 s
  └────────┬─────────┘
           ▼  意图 = 抓取
  ┌──────────────────────────────────────────┐
  │ 具身抓取闭环（embodied_grasp.py）         │
  │                                            │
  │  视觉线程 3 fps ──┐                        │
  │                   ├─→ 状态机 10 Hz          │
  │  力传感 20 Hz ────┘   ├─ 接触到            │
  │                       ├─ 夹到了  ← 力 + 边缘 │
  │                       ├─ 已移到B ← 到位+停稳 │
  │                       └─ 脱落 / 夹空        │
  │                                            │
  │  网页实时预览  http://<板子IP>:8082/        │
  └────────┬───────────────────────────────────┘
           ▼
    葡萄放到 B 点 → ✅ 成功
```

**★ 也可以跑旧流程**（`vision_grasp.py`，逻辑更简单、已验证 10/10）：

```
   你：「葡萄」→ ASR → 拍照识别 → 力控抓取 → 提起验证 → 成功
```

**★★ 两个流程的差别**：旧流程是**单帧快照**（拍一次就闭眼抓），
新流程是**持续观测 + 时序判定**（抓取全程都在看）。

### 三个模态各自解决什么

| 模态 | 作用 | 若没有它会怎样 |
|---|---|---|
| **语音** | 给出用户意图（要夹什么） | 只能靠固定程序，无法交互 |
| **视觉** | 确认目标真的在那里 | 会盲夹，可能夹到别的东西 |
| **力感知** | 判断夹到了、夹牢了、到硬件极限了 | 只能盲夹到固定位置，换个体积就失败 |

### 硬件清单

| 部件 | 型号 | 关键参数 |
|---|---|---|
| 主控 | MUSE Pi Pro | K1，8 核 RISC-V，2 TOPS NPU |

| 麦克风 | USB PnP Sound Device | 44100 Hz 单声道 |
| 力传感器 ×2 | PS01（AS7150） | UART 115200 8N1 |
| USB-UART ×2 | CH340 + PL2303 | 分别接两只传感器 |
| 舵机 | MG996R | **独立 5V 供电** |
| 夹爪 | 3D 打印平行夹爪 | 行程约 100 mm |

### 接线

**力传感器 → USB-UART**（两端都是 3.3V 逻辑，无需电平转换）：

```
PS01 3V3 ── 3V3      PS01 TXD ── RXD
PS01 GND ── GND      PS01 RXD ── TXD
```

**舵机**：

```
信号（橙）→ 物理引脚 22（GPIO_49）
电源（红）→ 独立 5V 电源 +
地（棕）  → 独立 5V 电源 −，并与板子 GND 相连
```

> ⚠️ **绝对不要从板子给舵机供电** —— 堵转电流可达 2.5 A，会拉垮板子。

## 关键工程发现

**这一节是本项目真正的内容 —— 每一条都是踩坑后测出来的。**

### 1. PS01 传感器需要隐藏的 `0xD4` 唤醒字节

所有文本命令都无响应。反编译厂商工具 `PS01Tool.exe` 后从字节码里找到：

```python
self.ser.write(bytes([212]))        # ← 0xD4，先发一个非打印字节
self.ser.write((cmd + "\r\n").encode())
```

**实际命令是 `D4 67 6E 73 74 0D 0A`，不是 `gnst\r\n`。**
逻辑分析仪没抓到，是因为它把不可打印的 `0xD4` 过滤掉了。

**还有第二个坑**：两只传感器启动行为不同 ——
A（CH340）会打印约 50 行初始化日志，**B（PL2303）一行都没有**。
必须等日志打完再发命令，且不能把"没有日志"当失败。

### 2. 力传感器必须用中位数，不能用均值

PS01 会周期性冒出一个孤立尖峰（实测 +11,300 计数）。

| 统计量 | 空载读数 | 后果 |
|---|---|---|
| 均值 | 被拉高约 1,900 计数 | 显示 **+1.2 N** ❌ |
| **中位数** | 不受影响 | 显示 +0.02 N ✅ |

### 3. 控制结构换了四版，前三版都是错的

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 力闭环**收敛到目标值** `abs(f−target) < tol` | ❌ 噪声（σ2.65N）比目标（1.2N）大，两指全开也报"力已到目标" |
| v2 | 自动算接触阈值 | ❌ 阈值算出 1.82 N，超过硬上限 1.50 N，逻辑死锁 |
| v3 | 位置为主 + 力作安全上限 | ⚠️ 能夹住，但**只能夹一个尺寸** |
| **v4** | **力到位即停 + 堵转识别** | ✅ 自适应 |

**核心区别**：

```
v1：|力 − 目标| < 0.15 N      ← 双边容差，噪声从两侧都能骗它
v4：力 ≥ 目标，连续 2 次       ← 单边阈值，噪声只能造成一次孤立假触发
```

**判"有没有跨过阈值"比判"等不等于目标值"稳健得多。**

### 4. 深紫葡萄的饱和度只有 33 —— 标准 HSV 区间完全失效

照抄网上的紫色区间 `(125,40,40)-(170,255,255)` 要求 S≥40、V≥40。
实测这颗葡萄 **S=33、V=39**，**每条都不满足，一个像素都框不到**。

正确的思路是**"深色 + 有一定色相"**：

```python
"grape": [
    ((120, 15, 15), (180, 255, 130)),   # 深紫：V≤130 排除白桌面
    ((20, 45, 25), (50, 255, 225)),     # 绿：H 20~50
]
```

**配套发现**：深色葡萄表面有高光，掩码会断裂，实心度只有 0.46~0.51，
而通用阈值是 0.72 —— **葡萄被自己的阈值判掉**。
所以阈值必须按颜色档自适应。

### 5. 按"圆度最高"选目标 → 把手指甲认成葡萄

```
原逻辑：圆度最高
结果：选中【手指甲】(r=34, 圆度 0.90)，报告"葡萄 置信度 0.81"
真正的葡萄 (r=62, 圆度 0.48) 被忽略
```

**两条修正**：

1. 选优改为**面积最大**（在 ROI 内）
2. 加**中心 ROI 约束**（只认画面中央 55%×70% 区域）

修正后：**1 个候选，圆度 0.97，置信度 0.95。**

### 6. 舵机堵转不是"力不足"

`脉宽 → 开口` 的映射**只在空载时成立**。葡萄挡住时舵机推不动，
脉宽继续减小但力不再上升：

```
780 µs +0.748 N → 770 µs +0.706 N → 760 µs +0.717 N → 750 µs +0.758 N
                脉宽走了 30 µs，力只变 0.05 N
```

**这不是力不足，是舵机的物理极限。** 判据：

```python
plateau = 最近 3 步力跨度 < 0.12 N
if plateau and f >= min_ok:  → ✅ 夹住
```

**没有这个识别会出现死循环**：目标 2.0 N > 舵机上限 1.37 N → 永远达不到
→ 一路降到机械底 → 报失败 → 重试时把目标抬更高 → 更不可能达到。

### 7. ASR 采样率错了，输出全是垃圾标签

录 3 秒 44100 Hz 音频直接送给期望 16000 Hz 的模型：

```
8.320 = 3.0 × 44100 / 16000 = 3.0 × 2.756     ← 数字完全吻合
```

模型把数据当成"慢了 2.76 倍的音频"，输出 `<|SAD|><|BGM|>` 这类垃圾。
**教训：先确认建模假设，再怀疑模型。**

### 8. PyAudio 会永久阻塞

`stream.read()` 在 USB 音频缓冲区欠载时永久阻塞，`Ctrl+C` 也打不断
（阻塞在 C 层）。实测在 1.3 秒处卡死。改用 `arecord` 子进程解决。

### 9. 关于"无损"的一个诚实结论

**原本的核心目标**是"防止夹坏葡萄"。实测发现：

```
舵机最大夹持力     1.2 ~ 1.4 N
葡萄破裂力（估计）  3 ~ 10 N
```

**这个夹爪物理上就夹不坏葡萄** —— 不是因为代码安全，是因为力不够大。

**真正的风险是"夹持力不足导致滑落"，而不是"夹坏"。**
所以力感知的价值从"防止破坏"变成了：

- 确认夹到了（力开始上升 = 接触到物体）
- 自适应物体尺寸（力到位就停）
- 识别硬件极限（堵转判定）

**这个结论写进了我们的报告 —— 测出什么就写什么。**

### 10. NPU 在 ASR 上没有收益

| 任务 | CPU | NPU |
|---|---|---|
| SenseVoice ASR | RTF 0.81 | RTF 0.82 |

**几乎相同**，说明瓶颈不在算力，而在**模型权重搬运的内存带宽**
（量化模型 229 MB）。

视觉识别是 OpenCV 算子，不是神经网络。
所以 NPU 用于**并发的持续任务** —— YOLOv8n 人手安全监控（已实测 19 fps）。
